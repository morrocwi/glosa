# S13 — Neighbour table (rewrite of the market-collision audit into the three-question format)

> **Tier: Dr.** This file rewrites `design/S13_market-collision-audit.md` (kept on disk, unchanged,
> as the underlying Dr-tier research readout) into the format `design/templates/knowledge/
> neighbour_table.md` requires, per founder ruling (request 31d/31e/31f/31g/31h/31i) and chair
> ruling A2/D4. It answers exactly one of the paper's three questions: **how do the nearest
> neighbours do it the same or differently** — never a priority or novelty contest, never "no tool
> does this," never "we take/reuse/borrow from them" unless a human explicitly instructed the
> adoption (no such instruction exists for any row below, so every row uses same/different/cited
> language only). This is deliverable 3 of the FOUNDATION_v0.2 synthesis round.
>
> **What changed from the original document, mechanically:** (1) the "already provides / RWI must
> concede / residual task" three-column shape is replaced by "problem they solve / their method /
> same as ours / different from ours / related work we cite"; (2) "concession"/"novel"/
> "unprecedented"/"residual claim" language is removed throughout; (3) every row without a fetched
> URL is marked `fetch_status: NOT_FETCHED`, tier `Open` (chair ruling D4) — this includes every
> row the original document tagged "Search-summary," a fourth evidentiary state that has no home
> in the project's own citation-card schema (`reviews/S13_honesty-usability.md` Must-fix 2; chair
> ruling C3 fixes this by reusing FOUNDATION §7.8's one `fetch_status` enum, which has no
> `SEARCH_SUMMARY` value, so those rows fold into `NOT_FETCHED` here rather than minting a fifth
> state); (4) every row's citation is still missing the literal fetched URL the original document's
> own header promised (`reviews/S13_honesty-usability.md` Must-fix 1) — this is **not fixed by
> this rewrite**, since re-fetching ~30 pages is outside a format-rewrite's scope; every row below
> states its `citation_card` as `PENDING` (not yet built as a real schema-conformant object) and
> its `fetched/verified` column honestly as `domain-only, no literal URL retained` where that is
> the true state, rather than silently upgrading the confidence. This is an **open item**, listed
> in the synthesizer's own report, not resolved here.
>
> Wording rule (founder, request 31f/31g/31h/31i): comparison text never says "we take/reuse/borrow
> from them" by default — it says only how RWI is the same as or different from a neighbour.
> "Adopted from" is used only when a human explicitly instructed taking something from a named
> source (a Blackbox Note line or `DECISIONS.yaml` row exists naming it). **No row below carries
> "adopted from" language** — no such instruction exists on record for any neighbour audited.

## Our own row (fill first, so neighbours are compared against something explicit)

- **Problem (R0/Blackbox-Note human words → lens formulation):** a person with no university, no
  lab, no research team needs to know, for one claim at a time, what licenses them to believe it
  (`the internal build plan (local file, not public)` §0; `FOUNDATION_v0.2.md` §1.1).
- **Method (spine stage / artifact):** a claim card answering five founder questions, tied
  mechanically to the Readout Condition's Existence-Attribution-Disclosure norm, gated by an
  independence ladder (I0–I5) before anything is released, under a maker-checker-approver release
  gate (MIMCG) — `FOUNDATION_v0.2.md` §§3–7.
- **What would make us wrong (falsifier):** a claim card mechanically passes every kernel gate
  (§3.3) while a genuinely independent human reviewer (I5) finds the underlying licensing test
  (Q2) or the AI-fill disclosure (Q3) false — showing the mechanical gate does not track the
  epistemic property it claims to track. See `FOUNDATION_v0.2.md` §3.1's own honesty note: Q2/Q3/Q4
  are presence-checkable, not correctness-checkable, by design — the falsifier is exactly a case
  where that gap is exploited undetected past K1.
