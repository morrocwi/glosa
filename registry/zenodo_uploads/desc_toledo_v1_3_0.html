What this is. Toledo is the programme's single permanent home for equations and their machine checks: a public git repository (https://github.com/morrocwi/toledo) whose tagged releases are deposited under this concept DOI. Scope is equations and Th_coqc only: registries, persistent codes (<root>/<D>.<nn>.v<k>), parents by code back to a root, an append-only lineage log, and Coq 8.20 sources whose file name is the code. Founder rules (2026-09-07): every equation of the programme is looked up here first and registered here before it is written or cited elsewhere; no AI agent in the programme may use an unregistered equation; the repository's EQUATION_SOURCE_POLICY.md states the same from the repository side.

Release v1.3.0 (counts computed from the files in the tag). 946 canonical entries (current 855, unverified 52, split 30, not_an_equation 9); 592 root rows. New in this release: (1) the Toledo MCP server and CLI under mcp/ — a local stdio server exposing 19 tools (search, get, status, lineage, ancestors/descendants, by root/domain/record, equivalence check with an explicit verdict, counts, index status, proposal registration and listing) over a SQLite FTS5 index built from the registry files; every write is a proposal file, never an edit of the registry; 214 tests; measured search latency p50 4.5 ms / p95 7.3 ms over 1,000 queries on the recording machine (2026-09-07); (2) a static read API exported from the same core and served from GitHub Pages (https://morrocwi.github.io/toledo/); (3) 34 readings registered from Effort Across Stochastic, Controlled, and Adaptive Worlds v0.3 (10.5281/zenodo.22622206) under the roots weld, EQ-015 and A.5, none equivalent to an existing entry under the equivalence criterion. Coq status per entry: closed 161, definition 357, wrapped_related 210, mapped_not_wrapped 119, open_prop 29, not_formalisable 70; 725 Coq files built one at a time, 207 identifiers closed. Catalogue rebuilt (A4, 283 pages).

Status and limits. K0 working release. Th_coqc / closed certifies the internal consistency of stated finite models, never empirical truth; a verdict from the server is a readout of the registry, not a truth claim. An AI assistant assisted under the author's direction; no AI system is an author or contributor.
